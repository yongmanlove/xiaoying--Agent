# 05 · 复盘

## 最难的问题

1. **冲突「只提示、不裁决」的边界**：冲突检测若只按 `topic_key` 分组，会被共用词（如「申请」）把无关文档带进 top_k 造成误报；最终通过语料设计（同域不同 `topic_key`）与「按组只做观察提示」把裁决权交还模型。
2. **引用可核验**：中文标点/空白会破坏子串匹配；用「空白归一化」而非模糊匹配，既保证逐字核验又不误杀。

## 踩过的坑

- Mock 的查询改写一度追加「制度 规定 时限」等词，导致「资料外」问题的重试**误命中**无关文档；改为仅去语气词后才走对 `insufficient_information` 路径。
- 追问场景 Mock 最初取「第一条」历史消息，导致把「那病假呢？」错检索成年假冲突；改为取最新 user 消息并加回归测试。
- 端到端跑 `examples/` 时才暴露以上两类问题——「实现 → 测试锁定 → 端到端样例」的分步门禁发挥了作用。

## 学习收获

- ReAct 的价值在于「观察驱动动作」，trace 里「工具结果 → 下一步动作」的因果关系是最有说服力的证据。
- 确定性校验（引用子串、状态机）是比提示词更可靠的硬保证。
